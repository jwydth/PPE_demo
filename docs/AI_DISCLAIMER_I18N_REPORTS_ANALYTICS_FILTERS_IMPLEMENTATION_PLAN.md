### 0.2 Feature 2 — Vietnamese/English reports

- There is **no i18n anywhere in this codebase today**. All report text (PDF via ReportLab,
  HTML/plain-text email) is hardcoded English, spread across four files:
  - `backend/app/services/reporting/insights.py` — 9 rule-based sentence generators + caveats,
    each returns fully-formed English prose with interpolated numbers.
  - `backend/app/services/reporting/pdf_renderer.py` (973 lines) — every section heading, table
    header, KPI card label, empty-state message, legend label is a literal English string.
  - `backend/app/services/reporting/report_data.py` — `_CATEGORY_LABELS`, `_RANGE_LABELS`,
    `_zone_scope_label()`, and all date/time formatting (`%d %b %Y, %H:%M` — English month
    abbreviations).
  - `backend/app/services/reporting/email_sender.py` — subject template + HTML/text body
    templates.
- **The PDF font is already Vietnamese-safe.** `backend/app/services/reporting/fonts/` contains
  vendored `DejaVuSans.ttf` / `DejaVuSans-Bold.ttf`, registered in `pdf_renderer.py`'s
  `_register_fonts()`. DejaVu Sans covers Vietnamese diacritics (this was confirmed and is why
  DejaVu was chosen over ReportLab's built-in Vera font when the PDF feature was first built —
  see `docs/features/PDF_REPORT_EMAIL_IMPLEMENTATION_PLAN.md` §0.2 item 6). **No font work needed.**
- **Explicit scope boundary (read this before touching anything):** incident *type* labels
  (e.g. "Missing Helmet and Vest", "Restricted Zone Incursion", "Fall Detected") are produced by
  `backend/app/services/incident_normalization.py`'s `ppe_type_label()` / `zone_type_label()` /
  `behavior_type_label()`. This module is shared by the **live dashboard**, not just reports.
  Translating it would ripple into the Incident Log, the 3D factory view, and the Live Feed panel
  — a much bigger change than "let me pick a report language." **Do not touch
  `incident_normalization.py`.** Zone names and camera names are also user-configured data, not
  translatable strings. This plan translates: section headings, table headers/column headers,
  KPI card labels, empty-state/placeholder text, the 9 generated insight sentences, the 4 caveat
  sentences, metadata labels, date formatting, and the email subject/body chrome — i.e. everything
  the report *itself* authors, not data the user or the detector produced. Severity words
  (Critical/High/Medium/Low) and category words (PPE/Zone/Behavior) get a **report-local display
  mapping** (see §2.3.4) — this only changes what's drawn on the PDF/email, not the underlying
  `severity`/`category` values used anywhere else in the app.
- **A latent bug you must fix while you're in here, regardless of language:**
  `pdf_renderer.py`'s `_zone_section()` (line 614) branches on
  `if data.zone_scope_label != "All zones":` — a **string comparison against a literal that is
  about to become translatable**. Once `zone_scope_label` can render as `"Tất cả khu vực"`, this
  comparison silently breaks (always true). Fix: add a `zone_id: int | None` field to `ReportData`
  and branch on `data.zone_id is not None` instead. See §2.2.2.
- Same class of bug in `_metadata_table()` (line 334): `style_a = styles["Mono"] if label_a ==
  "Generated at" else styles["Body"]` compares against a label that is about to be translated.
  Fix in §2.3.2.
- **No migration framework in this repo.** `backend/app/db/init_db.py` calls
  `SQLModel.metadata.create_all()`, which only creates whole missing tables — it never alters an
  existing one (confirmed in `backend/scripts/apply_new_indexes.py`'s own docstring, which exists
  specifically to patch this gap for indexes). Adding a `language` column to the existing
  `report_schedules` singleton table therefore needs a small idempotent `ALTER TABLE ... ADD
  COLUMN IF NOT EXISTS` script, mirroring `apply_new_indexes.py`'s pattern. See §2.2.5.
- `report_export-dialog.tsx` and `schedule-report-dialog.tsx` already have an identical, proven
  pattern for a per-request option (the zone selector): local `useState`, a `<select>` styled
  `w-full rounded-md border border-slate-200 px-2 py-1.5 text-xs`, synced into the request payload
  on submit. Reuse this exact pattern for the language selector — do not invent a new UI pattern.

### 0.3 Feature 3 — filter incidents by camera, by severity

- **Good news: severity filtering already exists in the service layer**, just not exposed.
  `backend/app/services/incident_service.py`'s `UnifiedIncidentService.list_incidents()` (line
  ~86) already accepts `severity: str | None` and applies it
  (`incidents = [i for i in incidents if i.severity == severity]`, line ~150) — confirmed by
  reading the method and by the existing test
  `test_list_incidents_filters_by_category_zone_and_severity` in
  `backend/tests/services/test_incident_service.py`. **`camera_id` filtering does not exist at
  any layer.**
- `backend/app/routers/analytics.py`'s `GET /analytics/incidents` only exposes `limit` and
  `zone_id` as query params — `severity` is silently unreachable from the API today.
- `UnifiedIncident` (the dataclass `list_incidents()` returns) already carries both `camera_id:
  int | None` and `severity: str` per row — no schema change needed on the read side.
  `UnifiedIncidentRead` (`backend/app/schemas/incident.py`) already mirrors both fields too.
- **The frontend already has a proven, deliberately-chosen filtering pattern to copy**, not
  invent: `frontend/src/components/analytics/analytics-dashboard.tsx` fetches the Live Feed
  **once, unfiltered** (`getUnifiedIncidents(FEED_LIMIT, null)`, `FEED_LIMIT = 30`), then filters
  it **client-side**:
  `const filteredFeed = selectedZone != null ? feed.filter((f) => f.zone_id === selectedZone) :
  feed;` (line 270). Zone selection itself happens by clicking nodes in a hand-rolled SVG "Zone
  Pulse" radial diagram, not a dropdown — that UI is zone-specific and not worth replicating for
  camera/severity. This plan adds `selectedCamera` / `selectedSeverity` state and two compact
  `<select>` dropdowns in the Live Feed panel header (title "Live Feed", ~line 556), following the
  same client-side-filter shape as the existing zone logic. This is a conscious, stated choice
  (§1, D3) to stay consistent with the existing pattern rather than adding new fetch parameters —
  it inherits the same known limitation the zone filter already has (a camera/severity with no
  incidents in the most recent 30 site-wide rows won't show, even if older matching incidents
  exist) — acceptable, and already true today for zone.
- The backend capability is still added and tested properly (not UI-only), because it's a real,
  independently useful API surface and the fix is small: expose `camera_id` + `severity` on the
  router, and add `camera_id` filtering to `UnifiedIncidentService.list_incidents()`.
- Camera names for the dropdown: `GET /cameras` already exists
  (`backend/app/routers/cameras.py`) and the frontend already has a typed client function
  `getCameras(): Promise<Camera[]>` in `frontend/src/lib/ppe-api.ts` (`Camera` = `{id, name,
  source_key, source_uri, home_zone_id, is_active, created_at, updated_at}`,
  `frontend/src/types/camera.ts`) — reuse it, don't write a new one.
- Severity options for the dropdown: `frontend/src/components/analytics/analytics-dashboard.tsx`
  already defines `SEVERITY_TONE: Record<SeverityLevel, {...}>` with the four canonical severity
  keys — reuse `Object.keys(SEVERITY_TONE) as SeverityLevel[]` exactly as two other spots in this
  same file already do (lines ~752, ~895), don't hardcode a second list.

```python
def t(key: str, language: str) -> str:
    """Looks up `key`, falling back to English if the language is unknown or
    the key has no entry for it. Never raises — a missing translation must
    not break report generation."""
    entry = _STRINGS.get(key)
    if entry is None:
        return key
    return entry.get(language, entry.get(DEFAULT_LANGUAGE, key))


def normalize_language(value: str | None) -> Language:
    """Coerces any input to a supported language code, defaulting to English
    for anything unrecognized (None, empty string, typo, future code)."""
    if value in LANGUAGES:
        return value  # type: ignore[return-value]
    return DEFAULT_LANGUAGE
```

```python
def _period_label(mode: str, language: Language) -> str:

def _add_trend_direction(insights: list[str], compare: AnalyticsCompare, language: Language) -> None:
    period = _period_label(compare.mode, language)
    if compare.prior_total == 0:
        if compare.current_total > 0:
            if language == "vi":
                insights.append(
                    "Đây là kỳ báo cáo đầu tiên có ghi nhận sự cố — chưa có dữ liệu kỳ "
                    "trước để so sánh."
                )
            else:
                insights.append(
                    "First reporting period with recorded incidents — no prior "
                    "baseline to compare against."
                )
        return
    direction_up = compare.current_total >= compare.prior_total
    if language == "vi":
        direction = "tăng" if direction_up else "giảm"
        insights.append(
            f"Số sự cố đã **{direction} {abs(compare.delta_pct):.1f}%** so với {period} "
            f"trước đó ({compare.current_total} so với {compare.prior_total})."
        )
    else:
        direction = "up" if direction_up else "down"
        insights.append(
            f"Incidents are **{direction} {abs(compare.delta_pct):.1f}%** vs the "
            f"previous {period} ({compare.current_total} vs {compare.prior_total})."
        )


def _add_hotspot_zone(insights: list[str], summary: AnalyticsSummary, language: Language) -> None:
    if not summary.zone_totals:
        return
    site_total = sum(z.total for z in summary.zone_totals)
    if site_total <= 0:
        return
    top = max(summary.zone_totals, key=lambda z: z.total)
    share = top.total / site_total
    if share < 0.30:
        return
    if language == "vi":
        insights.append(
            f"**{top.zone_name}** chiếm {share * 100:.0f}% tổng số sự cố "
            f"({top.total}/{site_total}) — cao nhất trong số {len(summary.zone_totals)} khu vực."
        )
    else:
        insights.append(
            f"**{top.zone_name}** accounts for {share * 100:.0f}% of all "
            f"incidents ({top.total} of {site_total}) — the highest of "
            f"{len(summary.zone_totals)} zones."
        )


def _add_dominant_type(insights: list[str], summary: AnalyticsSummary, language: Language) -> None:
    if not summary.type_counts or summary.grand_total <= 0:
        return
    top = max(summary.type_counts, key=lambda t: t.count)
    share = top.count / summary.grand_total
    if share < 0.25:
        return
    if language == "vi":
        insights.append(
            f"**{top.type}** là loại sự cố xảy ra nhiều nhất ({top.count} lần, "
            f"chiếm {share * 100:.0f}% tổng số)."
        )
    else:
        insights.append(
            f"**{top.type}** is the most frequent incident type ({top.count} "
            f"occurrences, {share * 100:.0f}% of total)."
        )


def _add_critical_severity(insights: list[str], summary: AnalyticsSummary, language: Language) -> None:
    if summary.severity_counts.Critical <= 0:
        return
    if language == "vi":
        insights.append(
            f"**{summary.severity_counts.Critical} sự cố Nghiêm Trọng** cần được xem xét "
            f"ngay lập tức."
        )
    else:
        insights.append(
            f"**{summary.severity_counts.Critical} Critical** incidents require "
            f"immediate review."
        )


def _add_severity_shift(insights: list[str], compare: AnalyticsCompare, language: Language) -> None:
    for delta in compare.severity_breakdown:
        if delta.prior <= 0 or delta.current <= delta.prior:
            continue
        growth = (delta.current - delta.prior) / delta.prior
        if growth < 0.50:
            continue
        multiplier = delta.current / delta.prior
        sev_label = _severity_label(delta.severity, language)
        if language == "vi":
            if multiplier >= 2:
                insights.append(
                    f"Sự cố mức độ **{sev_label}** đã tăng hơn gấp đôi "
                    f"({delta.prior} → {delta.current})."
                )
            else:
                insights.append(
                    f"Sự cố mức độ **{sev_label}** đã tăng {growth * 100:.0f}% "
                    f"({delta.prior} → {delta.current})."
                )
        else:
            if multiplier >= 2:
                insights.append(
                    f"**{sev_label}**-severity incidents more than doubled "
                    f"({delta.prior} -> {delta.current})."
                )
            else:
                insights.append(
                    f"**{sev_label}**-severity incidents rose {growth * 100:.0f}% "
                    f"({delta.prior} -> {delta.current})."
                )
        return


def _add_peak_bucket(insights: list[str], trend: AnalyticsTrend, language: Language) -> None:
    totals = [sum(p.zone_totals.values()) for p in trend.points]
    if not totals or sum(totals) <= 0:
        return
    mean = sum(totals) / len(totals)
    if mean <= 0:
        return
    peak_idx = max(range(len(totals)), key=lambda i: totals[i])
    peak_value = totals[peak_idx]
    if peak_value < 2 * mean:
        return
    if language == "vi":
        insights.append(
            f"Hoạt động cao điểm vào **{trend.points[peak_idx].date}** ({peak_value} "
            f"sự cố, gấp {peak_value / mean:.1f} lần trung bình)."
        )
    else:
        insights.append(
            f"Peak activity on **{trend.points[peak_idx].date}** ({peak_value} "
            f"incidents, {peak_value / mean:.1f}x the average)."
        )


def _add_quiet_zones(insights: list[str], summary: AnalyticsSummary, language: Language) -> None:
    quiet = [z.zone_name for z in summary.zone_totals if z.total == 0]
    if not quiet:
        return
    names = ", ".join(quiet)
    if language == "vi":
        insights.append(f"{len(quiet)} khu vực không ghi nhận sự cố nào: {names}.")
    else:
        noun = "zone" if len(quiet) == 1 else "zones"
        insights.append(f"{len(quiet)} {noun} recorded no incidents: {names}.")


def _add_camera_coverage(insights: list[str], summary: AnalyticsSummary, language: Language) -> None:
    if summary.total_cameras <= 0 or summary.active_cameras >= summary.total_cameras:
        return
    if language == "vi":
        insights.append(
            f"Sự cố được ghi nhận trên {summary.active_cameras}/{summary.total_cameras} "
            f"camera đang hoạt động."
        )
    else:
        insights.append(
            f"Incidents were recorded on {summary.active_cameras} of "
            f"{summary.total_cameras} active cameras."
        )


def _add_all_clear(insights: list[str], summary: AnalyticsSummary, language: Language) -> None:
    if summary.grand_total != 0:
        return
    if language == "vi":
        insights.append("Không có sự cố nào được ghi nhận trong kỳ này tại bất kỳ khu vực giám sát nào.")
    else:
        insights.append("No incidents recorded in this period across any monitored zone.")
```

```python
"""One-off, idempotent schema patch: adds the `language` column to
`report_schedules` for an already-existing database.

There's no migration framework in this project (see app/db/init_db.py —
schema is plain SQLModel.metadata.create_all(), which only creates whole
missing tables and never alters an existing one). This mirrors
scripts/apply_new_indexes.py's pattern, but for a column instead of an
index. Safe to re-run — IF NOT EXISTS makes it a no-op on a DB that already
has the column (e.g. one created fresh after this change landed, where
create_all() already included it).
"""

from sqlalchemy import text

from app.db.session import get_engine


def add_report_language_column() -> None:
    engine = get_engine()
    with engine.begin() as conn:
        conn.execute(
            text(
                "ALTER TABLE report_schedules "
                "ADD COLUMN IF NOT EXISTS language VARCHAR(8) NOT NULL DEFAULT 'en'"
            )
        )
    print("ok: report_schedules.language")


if __name__ == "__main__":
    add_report_language_column()
```

```tsx
                    </option>
                  ))}
```

```tsx
                <select
                  value={selectedSeverity ?? ""}
                  onChange={(e) => setSelectedSeverity((e.target.value || null) as SeverityLevel | null)}
                  className="flex-1 rounded-md border border-slate-200 px-2 py-1 text-xs outline-none focus:border-slate-400"

                  {(Object.keys(SEVERITY_TONE) as SeverityLevel[]).map((sev) => (

                      {sev}

              </div>
              <div className="mt-2 flex-1 overflow-y-auto">
                {filteredFeed.length === 0 && (
```

## 7. Known limitations to write down, not solve

- **Feature 2 does not translate incident type labels, zone names, or camera names** — by
  design, see §0.2. A future "translate the whole app" effort would need to touch
  `incident_normalization.py` and is a materially bigger change than this one.
- **Feature 2's Vietnamese dates are numeric (`dd/mm/yyyy`), not month-name Vietnamese** — a
  deliberate simplification (§1 D3), not a placeholder to fix later unless specifically requested.
- **Feature 3's camera/severity filters operate on the same 30-row unfiltered fetch the existing
  zone filter already uses** — a camera/severity combination whose only matches are older than
  the 30 most recent site-wide incidents won't appear. This is an accepted, pre-existing tradeoff
  (already true for zone today), not a new regression.
- **The Incident Log tab (`IncidentPanel` in `dashboard-shell.tsx`, driven by
  `getSafetyEvents()`) is a separate component from the Analytics tab's Live Feed panel and is
  intentionally left untouched** — it has no filters at all today (zone, camera, or severity) and
  adding them there is a separate, larger scope decision than what was requested.
